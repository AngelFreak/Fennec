# Sending by QR code (phone protocol v2)

Replaces pairing (protocol v1 in `2026-10-06-android-recorder.md`). There
are no paired phones any more: each time recordings go from the phone to
Fennec, Fennec shows a fresh QR code and the phone scans it.

## Why

Pairing kept a secret on the phone indefinitely, kept Fennec listening on
the network whenever it was open, and needed mDNS to find Fennec again
when its address changed. People found it confusing ("is it paired? is it
sending?"). A code per transfer is explicit: you see it happen, and when
the dialog closes nothing is listening.

Given up: automatic background sending, typing an address by hand (USB
covers phones without a camera), and adding or changing projects from the
phone (the phone still files recordings under Fennec's projects).

## Flow

1. Fennec: **Receive from phone** (Files page, Settings → Phone). Fennec
   starts listening and shows a QR code. The listener stops when the dialog
   closes, when Stop is pressed, or after 10 minutes with nothing
   happening.
2. Phone: **Send to Fennec** opens the camera. Scanning the code (or opening
   the `fennec://send` link from another camera app) connects, then sends
   every recording that has not been sent, one at a time, with progress.
3. Fennec shows the phone's name and each recording as it arrives. When
   the phone says it is done, Fennec shows "Received N recordings" and stops
   listening after the dialog is closed.

## QR code

`fennec://send?h=<ip:port>&pin=<pin>&t=<ticket>&n=<computer name>`

- `pin`: SHA-256 of the certificate's SubjectPublicKeyInfo, unpadded
  URL-safe base64 (unchanged from v1). The phone accepts only this
  certificate.
- `t`: the ticket, 16 random bytes as unpadded URL-safe base64 (22 chars).
  Used once: the first `hello` with it claims the transfer.
- `n`: percent-encoded.

## Transport

HTTPS with Fennec's self-signed certificate (unchanged, kept in
`~/.local/share/fennec/sync/`). One request per connection; bodies need a
Content-Length and may be up to 4 MB. Every answer is JSON; errors are
`{"error": <code>, "message": <text to show>}`.

## Endpoints

| Method and path | Auth | Purpose |
|---|---|---|
| `POST /v1/hello` | none | `{ticket, device_name}` → `{session, name, id, version, protocol: 2, projects, templates, default_template, project_colors}` (the fields after `session` are as v1's `/v1/info`). 403 `no_ticket` (Fennec is not receiving or the code expired), `used` (another phone already scanned it), `wrong_ticket`; five wrong tickets close the code |
| `PUT /v1/recordings/{id}` | session | Announce, as v1 |
| `PUT /v1/recordings/{id}/audio?offset=N` | session | One chunk, as v1 |
| `POST /v1/recordings/{id}/complete` | session | As v1; answers `state: "queued"` and `document_id` |
| `POST /v1/done` | session | `{}`: the phone has sent everything it meant to. Ends the session |
| `POST /v1/pair` | none | 410 `update_app`: an older Fennec Recorder |

`session` is 32 random bytes, unpadded URL-safe base64, sent as
`Authorization: Bearer <session>`. Without a valid one: 401 `no_session`
("Fennec stopped receiving. Scan a new code in Fennec to send."). A
session lasts until `done`, Stop, or the dialog closes.

Uploads are no longer tied to a phone: an unfinished upload resumes on the
next scan by id (announce answers `received`), and a different size or
checksum under the same id starts over.

Removed from v1: `/v1/pair`'s pairing, `GET /v1/info` (in `hello`),
`GET /v1/recordings` (the phone no longer follows transcription),
`POST`/`PUT /v1/projects`, `DELETE /v1/devices/self`, and mDNS.

## Phone

- A recording is **Not sent** until `complete` answers, then **Sent**.
- The projects and templates from `hello` are kept for the pickers until
  the next scan.
- On upgrade the app forgets the old pairing (address, pin, device secret
  and its Keystore key).
- USB transfer is unchanged; its sidecar no longer has a `device_id`.

## Security

- The pin in the code means only this Fennec can receive.
- The ticket is single-use and lives only while the dialog is open, so a
  photographed code is useless once the phone has scanned it, and Fennec
  shows which phone is sending, with Stop.
- No secret is stored anywhere after a transfer; nothing to revoke.
